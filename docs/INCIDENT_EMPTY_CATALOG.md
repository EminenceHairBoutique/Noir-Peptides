# Incident — empty catalog after 0023 (and the audit that followed)

## Symptom
`/shop` rendered "NO RESEARCH MATERIALS FOUND · 0 materials" on production
immediately after running the schema-reconcile migration 0023.

## Root cause
Production had **RLS disabled** on the catalog tables, with **stale policy
definitions** sitting under the canonical policy names — old
attestation-gated versions (`using (is_attested())`) from an earlier
migration generation. While RLS was off those policies were inert, so
anonymous catalog reads worked.

0023 correctly enabled RLS everywhere to match the code. But its policy
creation was guarded **by name only**:

```sql
if not exists (select 1 from pg_policies where ... policyname='products_public_read') then
  create policy "products_public_read" ... using (true);
end if;
```

The name already existed, so the guard skipped — leaving the stale
*attestation-gated* definition in force. With RLS now enforcing, anonymous
visitors matched no rows → empty catalog. (Reproduced exactly in a scratch
Postgres with a real non-owner role: 3 rows before, permission-denied/0 after,
3 again once the policy was recreated.)

## Fixes shipped

1. **`0024_policy_reconcile.sql`** — deterministic: `drop policy if exists`
   + `create policy` for **all 53** golden policies (plus RLS enables), so the
   end state matches the code regardless of stale definitions. Generated by
   introspecting the golden schema; idempotent (validated across two runs).
   Verified with a real anon-like role afterwards: products 44, variants 96,
   categories 8, tiers 480, published COAs 19 — while `orders` stayed 0 and
   `label_configs` stayed inaccessible (gating intact).
   *All app writes go through service-role `/api` endpoints (audited: zero
   direct client-side writes), so write paths are unaffected.*

2. **Client-side catalog fallback** (`src/lib/catalog.js`) — the storefront no
   longer depends on the DB being reachable/correct to show products. If a
   catalog read errors **or returns zero rows**, the helpers fall back to the
   same bundled catalog the prerenderer uses. Proven headlessly: with all
   Supabase traffic blocked, `/shop` renders 44 product cards and "44
   materials" instead of the empty state, with no page errors.
   Dynamic/DB-only data (stock, COAs, orders, labels) is never faked, and
   purchase remains gated server-side.

## Lesson / guard
Name-guarded policy creation cannot repair drifted *definitions* — only
absent ones. Any future reconcile must drop+recreate policies (as 0024 does).
